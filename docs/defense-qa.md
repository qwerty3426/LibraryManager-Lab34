# Defense Q&A — BankSystem

# 1. Чому ви використали Clean Architecture?

Clean Architecture дозволяє:
- розділити відповідальності;
- ізолювати бізнес-логіку;
- спростити тестування;
- легше масштабувати систему.

---

# 2. Для чого потрібен IRepository<T>?

IRepository<T> забезпечує абстракцію над persistence layer.

Це дозволяє:
- змінювати спосіб збереження;
- не змінювати бізнес-логіку;
- дотримуватись DIP.

---

# 3. Чому використано Generic Repository Pattern?

Generic repository:
- зменшує дублювання;
- дозволяє працювати з різними типами;
- спрощує підтримку коду.

---

# 4. Навіщо використаний Strategy Pattern?

Strategy Pattern використовується для:
- різних алгоритмів комісії;
- розширення системи без зміни BankService.

---

# 5. Які принципи SOLID реалізовані?

У проєкті використано:

- SRP;
- OCP;
- DIP.

---

# 6. Чому persistence реалізований через JSON?

JSON:
- простий;
- читабельний;
- не потребує СУБД;
- зручний для навчального проєкту.

---

# 7. Які типи тестів реалізовані?

Реалізовано:
- unit tests;
- integration tests;
- coverage testing.

---

# 8. Що перевіряють integration tests?

Integration tests перевіряють:
- JsonRepository<T>;
- файлову систему;
- serialization/deserialization;
- persistence logic.

---

# 9. Яке тестове покриття має система?

Покриття:
- Line coverage: 88.7%;
- Branch coverage: 83.3%.

---

# 10. Які проблеми були під час розробки?

Основні проблеми:
- persistence;
- обробка помилок;
- тестування JSON;
- організація архітектури.

---

# 11. Що можна покращити в майбутньому?

Можливі покращення:
- база даних;
- ASP.NET frontend;
- dependency injection container;
- authentication;
- async operations.

---

# 12. Чому проєкт можна вважати завершеним?

Тому що:
- реалізована основна функціональність;
- архітектура стабільна;
- тестування пройдено;
- документація завершена;
- підготовлений реліз v1.0.0.
